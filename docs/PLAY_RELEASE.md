# Google Play 公開 手順書

最終更新: 2026-08-15 / 確認日時点の要件に基づく

---

## 最重要: 最短経路の考え方

**律速はコードではなくテスターです。**

個人開発者アカウント（2023年11月13日以降に作成）は、製品版を公開する前に
**12人以上のテスターが14日間連続でオプトインしているクローズドテスト**が必須。
14日は連続でなければならず、途中で12人を割るとカウントがやり直しになる。

したがって最短経路はこうなる。

```
Play Console 登録（本人確認に数日）
        ↓
署名鍵の作成
        ↓
★ とにかく早く AAB をクローズドテストに上げてテスターを集め始める ★
        ↓
   14日間待つ ←──────┐
        ↓             │ この期間にストア掲載情報を仕上げる
   製品版アクセスを申請 │ （並行作業。待ち時間を無駄にしない）
        ↓             │
   審査（概ね7日以内）─┘
        ↓
      公開
```

**ストア掲載情報を完璧にしてからテストを始めてはいけない。** 逆にすること。

> **例外**: 法人として組織アカウントを登録した場合、この12人×14日の要件は**免除**される。
> 個人事業主/法人をお持ちなら検討の余地あり（ただし登録要件が別途厳しくなる）。

## Phase 1. Play Console に登録する（本人確認に数日かかるので最初に）

1. https://play.google.com/console にアクセス
2. **個人**アカウントで登録（$25 買い切り）
3. 本人確認書類を提出 → **承認まで数日かかることがある。ここが最初の待ち時間**

> この待ち時間中に Phase 2 と Phase 3 の準備を進めておくこと。

## Phase 2. 署名鍵を作る ★これを失うと二度と更新できません

**私（Claude）は実行しません。** パスワードを扱うためです。

### 2-1. キーストアの作成

Android Studio → **Build > Generate Signed App Bundle / APK > Android App Bundle > Create new...**

入力する主な項目:

- **Key store path**: プロジェクト外の安全な場所（例: `C:\Users\mytho\keys\appshelf-release.jks`）
- **Password**: キーストアと鍵の両方
- **Alias**: `appshelf` など
- **Validity**: 25年以上（既定のままでよい）
- **Certificate**: 氏名・組織など（後から変更不可だが、表に出るものではない）

### 2-2. バックアップ ★必須

**この鍵を失うとアプリを永久に更新できません。** 最低2か所に保管すること。

- 外付けドライブ / USB メモリ
- パスワード管理ソフトの添付ファイル機能
- クラウドストレージ（暗号化して）

### 2-3. プロジェクトに紐付ける

プロジェクトルート `D:\dev_app` に `keystore.properties` を作る。

```
storeFile=C\:\\Users\\mytho\\keys\\appshelf-release.jks
storePassword=（作成時のパスワード）
keyAlias=appshelf
keyPassword=（作成時のパスワード）
```

- **このファイルと `.jks` は `.gitignore` 済み。** 絶対にコミットしないこと
- `app/build.gradle.kts` はこのファイルがあれば自動でリリース署名に使う

### 2-4. Play App Signing

初回アップロード時に **Play App Signing を使う**を選ぶ（既定）。
Google が本番の署名鍵を預かってくれるため、手元の鍵を失っても復旧できる。**強く推奨。**

## Phase 3. 最小限の情報で AAB をクローズドテストに上げる ★最優先

### 3-1. AAB をビルド

```bash
$env:JAVA_HOME='D:\dev_tools\jdk\jdk-17.0.20+8'; $env:ANDROID_HOME='D:\dev_tools\android-sdk'; .\gradlew.bat bundleRelease
```

出力: `app/build/outputs/bundle/release/app-release.aab`

**署名されているか必ず確認すること。** `keystore.properties` が無いと署名なしでビルドされ、
アップロードで弾かれる。

### 3-2. Play Console の「アプリ内容」を埋める

Console のダッシュボードに**やるべきことの一覧が出る**ので、それに従うのが確実。
以下は本アプリでの回答内容。

| 項目 | 回答 |
|---|---|
| プライバシーポリシー | URL が必須（→ Phase 3-3） |
| アプリのアクセス権 | 制限なし（ログイン不要） |
| 広告 | **広告を含まない** |
| コンテンツのレーティング | アンケートに回答。ユーティリティなので全年齢想定 |
| **データセーフティ** | **「データを収集しません」「データを共有しません」** |
| ターゲット層 | 13歳以上など（子供向けではない） |
| 政府関連アプリ | いいえ |
| 金融機能 | なし |

> **データセーフティで「収集しません」と申告できる根拠**:
> このアプリは `android.permission.INTERNET` を宣言していないため、
> 技術的にデータを送信できない。これは検証済み（`aapt2 dump permissions` で確認可能）。
> **強力なアピールポイントなので、ストア説明文にも明記すること。**

### 3-3. プライバシーポリシーを公開する

原稿は `docs/PRIVACY_POLICY.md` にある。

**ソースを公開リポジトリで出すことにしたので、ポリシー専用のリポジトリは不要。**
同じリポジトリの `docs/` フォルダから GitHub Pages を出せる。

1. https://github.com/Rutar999/app_inventory の **Settings > Pages** を開く
2. **Source** を `Deploy from a branch`、**Branch** を `main` / `/docs` に設定
3. 数分後に次の URL が有効になる

```
https://rutar999.github.io/app_inventory/PRIVACY_POLICY
```

4. その URL を Play Console のプライバシーポリシー欄に入力

> Pages のホスト名は常に小文字になる（`Rutar999` → `rutar999`）。
> リンク切れを疑う前にここを確認すること。

### 3-4. 権限の申告

| 権限 | 申告 |
|---|---|
| `PACKAGE_USAGE_STATS` | 機微な権限。**アプリ内に用途説明画面あり**（設定 → 使用状況へのアクセス、およびオンボーディング4ページ目）。ストア説明文にも用途を記載 |
| `REQUEST_DELETE_PACKAGES` | 通常権限。宣言のみ |
| `QUERY_ALL_PACKAGES` | **使っていない。** `<queries>` 方式のため権限宣言フォームは不要 |

### 3-5. クローズドテストのトラックを作って公開

**テスト > クローズドテスト** でトラックを作り、AAB をアップロードしてリリースを作成。

## Phase 4. テスターを12人集める ★最長のボトルネック

### 4-1. テスターの登録

- メールアドレスのリスト、または Google グループで登録
- **Google アカウントのメールアドレス**が必要（Gmail 以外でも Google アカウントなら可）

### 4-2. オプトインしてもらう

1. Console が発行する**オプトイン URL** をテスターに配る
2. テスターがそのページで「テスターになる」を押す ← **ここまでやってもらわないとカウントされない**
3. Play ストアからアプリをインストールしてもらう

### 4-3. 14日間維持する

- **12人を1日でも下回るとカウントがやり直し**
- 途中でオプトアウトした人は数えられない
- **余裕をもって15人程度**集めること
- この期間中もアプリの更新は上げてよい（むしろ推奨）

### 4-4. 声のかけ方

家族・友人・職場の同僚・SNS のフォロワー・開発者コミュニティなど。
「Android スマホを持っていて、アプリを1つ入れて14日間そのままにしてくれる人」を探すだけでよい。
毎日使ってもらう必要はない。

## Phase 5. ストア掲載情報を仕上げる（Phase 4 の14日間と並行）

### 5-1. 必要な素材

| 素材 | 仕様 | 状況 |
|---|---|---|
| アプリアイコン | 512×512、32bit PNG | ✅ `store/play-icon-512.png` |
| フィーチャーグラフィック | 1024×500 PNG | ✅ `store/play-feature-graphic-1024x500.png` |
| スクリーンショット | 最低2枚、推奨8枚。**実機の実画面** | ✅ `store/screenshots/` に6枚 |
| 短い説明 | 80文字以内 | 下記の案 |
| 詳細な説明 | 4000文字以内 | 下記の案 |

> **スクリーンショットの仕様上の注意**
>
> Play は「**長辺は短辺の2倍まで**」を要求する。この検証機の画面は 1256×2760（1:2.197）で
> **そのままでは要件を超える**。上下のシステムバーを各130px 切り落として
> **1256×2500（1:1.99）** に加工してある。アルファチャンネルなしの 24bit PNG に変換済み。
>
> 撮り直す場合は同じ加工が必要。実機の画面をそのまま上げると弾かれる。

> **フィーチャーグラフィックについて**
>
> Play は表示面によって端をトリミングすることがあるため、文字は中央寄りに置いてある
> （本文の右端 x=910、余白 114px）。作り直す場合も端に文字を寄せないこと。
> キャッチコピーは「容量・未使用・権限を、ひと目で」＋「広告なし / 通信なし」。

**撮影済みの6枚**（すべて使用状況アクセスを許可した状態＝実データ入り）

| ファイル | 内容 |
|---|---|
| `01_home.png` | ダッシュボード（233本 / 80GB / 未使用111 / 回収可能32GB / 容量ランキング） |
| `02_applist.png` | アプリ一覧（容量と最終起動日つき） |
| `03_permissions.png` | 権限タブ（カテゴリ別の付与済み件数） |
| `04_permission_lookup.png` | 権限の逆引き（マイクを使えるアプリ） |
| `05_detail.png` | アプリ詳細（容量内訳・使用状況） |
| `06_multiselect.png` | 複数選択モード（順次アンインストールの入口） |

### 5-2. 短い説明（案・44文字）

```
インストール済みアプリを一覧・分析して、消す判断ができる形で見せます。通信は一切しません。
```

### 5-3. 詳細な説明（案）

```
「このアプリ、いつから使ってない？」「どれが容量を食っている？」
「マイクにアクセスできるアプリはどれ？」

アプリ棚卸しは、その3つの問いに答えるためのツールです。
ホーム画面を置き換えるランチャーではなく、年に数回開いて整理するための道具として作りました。

■ できること
・インストール済みアプリの一覧、検索（ひらがな・カタカナのゆらぎに対応）、並び替え
・容量ランキング（本体／データ／キャッシュの内訳つき）
・最終起動日と使用時間から「使っていないアプリ」を検出
・危険度の高い権限からの逆引き（例:「マイクを使えるアプリ 8件」）
・タグ、お気に入り、非表示による自分なりの分類
・選んだアプリを順番にアンインストールする導線
・容量と使用時間の長期推移グラフ
・一覧の CSV / JSON 書き出し

■ プライバシー
このアプリはインターネット権限を持っていません。
読み取った情報が端末の外に出ることは、技術的にありません。
広告SDKも解析SDKも一切組み込んでいません。

■ 権限について
・使用状況へのアクセス（任意）… 最終起動日・使用時間・容量の表示にのみ使用します。
  許可しなくても、一覧・検索・タグ・権限の確認はすべて使えます。
・アプリの削除リクエスト … 1本ずつ Android の確認画面を経由します。
  無確認での削除や一括削除は Android の仕様上できません。

■ できないこと（Android の制約）
・他のアプリの権限を取り消すこと（設定画面へ案内するところまでです）
・システムアプリの削除・無効化
・確認なしの一括アンインストール
・このアプリ内の「非表示」はホーム画面には影響しません
```

> **「できないこと」を先に書いておくと低評価レビューが目に見えて減ります。**
> このアプリは Android の制約が多いので、特に効果が大きいはずです。

### 5-4. スクリーンショットに入れたい画面

1. ホーム（ダッシュボード。総数・容量・未使用・回収可能）
2. アプリ一覧（アイコン付き、容量と最終起動日が見える状態）
3. 権限タブ（逆引きの件数バッジ）
4. 権限の逆引き一覧（「マイクを使えるアプリ」）
5. アプリ詳細（容量内訳・権限・推移グラフ）
6. 複数選択 → 順次アンインストールの確認ダイアログ

> **使用状況アクセスを許可した状態で撮ること。** 未許可だと「—」ばかりの画面になる。

## リリース前チェックリスト

- [ ] `versionCode` を上げた（**更新のたびに +1 が必須**。同じ番号は再アップロードできない）
- [ ] `versionName` を更新した
- [ ] `keystore.properties` と `.jks` が Git に含まれていない
- [ ] **リリースビルド（R8 有効）で実機動作を確認した** ← デバッグでは動いてリリースで落ちる、はよくある
- [ ] ダークテーマで表示崩れがない
- [ ] 使用状況アクセスを**未許可のまま**でも一通り操作できる
- [ ] TalkBack を ON にして主要画面を操作できる（**未実施**）
- [ ] スクリーンショットは実機の実画面（モックアップは規約違反になり得る）
- [ ] プライバシーポリシー URL が実際に開ける
