### B-5. マネタイズ方針 — ✅ 決定済み（2026-08-15）

**まず無料・広告なしで公開する。** 収益化は公開後に実データを見てから判断する。

**広告を入れない理由:**

1. **差別化が壊れる。** このアプリの売りは「INTERNET 権限を持たない＝技術的に送信できない」
   という一点で、オンボーディング・プライバシーポリシー・データセーフティ申告・
   ストア説明文のすべてに組み込まれている。広告 SDK は INTERNET 権限を必須とし、
   これら全部の書き換えが必要になる
2. **起動頻度と相性が悪い。** 「年に数回開く棚卸しツール」という設計上、
   広告表示回数が極端に少ない。1万ダウンロードでも年間 2〜5万円程度の概算
3. 要件定義書 §1.4 で「非目標」として明示的に除外していた項目でもある

**将来の選択肢（公開後に検討）:**

| 手段 | INTERNET 権限 | 「通信しない」と両立 |
|---|---|---|
| **買い切り有料の Pro 版を別アプリで出す** | 不要 | ✅ **最有力** |
| GitHub Sponsors（アプリ外・ストア掲載情報や README に記載） | 不要 | ✅ |
| 広告 / アプリ内課金 / サブスク | 必要 | ❌ |

Pro 版を出す場合は **Gradle の productFlavors** で 1 つのコードベースから 2 つ作る。
**既存機能は無料版に全部残し、Pro には新規機能（F-14/24/32/36/44/45）だけを入れる**こと。
公開後に既存機能を有料化するとレビューが荒れる。

> **アプリ内に寄付リンクを置くのは避けること。** Play は原則としてアプリ内から
> 外部の課金導線へ誘導することを禁じている。寄付はストア掲載情報や GitHub 側に留める。

`.release` を付けると Play の URL（`...details?id=io.github.rutar999.appshelf.release`）や

### 実装前に見つけた既存の不具合（修正済み）

日次スナップショットに保存していたのが `foregroundTotal`（**365日ローリング合計**）だった。
日付順に並べてもほぼ単調増加するだけで「最近使わなくなった」が読み取れない。
**`foreground30d`（30日窓）に変更**した。値が下がる＝使わなくなった、と素直に読める。

### 制約（ユーザーに見える形で説明している）

記録は「アプリを開いた日に1回」しか増えない。したがって使い始めはグラフが出ない。
黙って空欄にせず、`R.string.detail_trend_insufficient` で理由を説明している。
**さらに、使用状況アクセスが未許可のときはスナップショット自体が保存されない**
（`AppRepository.performRefresh` が未許可時に早期 return するため）。

### 検証状況

検証機は使用状況アクセスが未許可でスナップショットが 0 件のため、
**一時的にサンプルデータを埋め込んで描画のみ確認し、直後に除去した**。
容量が右肩上がり、使用時間が 1時間30分 → 0 へ減少する様子が正しく描画された。
**実データでの動作は未検証。** 使用状況アクセスを許可して数日使ってから要確認。
